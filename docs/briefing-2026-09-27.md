## Main issues

### 1. The analyzer cannot see most of the hits in a front-camera diddle

This is the problem to solve. It is not a clock sync bug and it is not "the AI was not trained."

On 60 in-spec phone takes (front camera, clean, no clap, the rudiment starts immediately and runs 2 to 4 bars), the shipped detector finds about half the sounds. Median strikes per audio hit: 0.54. That caps a fair one-to-one match near 54%. Measured median match at the recorded timing was about 31% (an earlier pass on the stored reports read about 24% agreement). Best time offset across a take had a median of +2 ms, so the picture and the sound are not systematically late. The offset spread across takes was 175 ms, which is scatter, not one delay to subtract. Widening the match window to 200 ms only reached about 49.5%, which is the density ceiling, not a timing fix.

Split by rudiment, using the shipped detector (wrist low points only):

| Rudiment | Strikes per hit | Match |
| --- | --- | --- |
| Single Stroke Roll | 0.85 | 70% |
| Flam | 0.86 | 35% |
| Double Stroke Open Roll | 0.49 | 35% |
| Five Stroke Roll | 0.53 | 32% |
| Single Paradiddle | 0.53 | 26% |

Singles work because each note is its own downstroke. Doubles, rolls, and paradiddles fail because a front camera shows one wrist dip for two sounds. The second note is in the stick, and stick tips are not tracked. Flams are closer to one strike per sound, and they miss because the low-point time does not land inside the verify window (default 40 ms, at least 60 ms under 50 fps). Pose coverage on these takes is about 1.0, so the body is in frame. The miss is the strike rule.

Hand landmarks (fingertips and palm) are already computed. They feed an experimental grip proxy. They are not used to place strikes.

### 3. There is no drum model

MediaPipe Pose Landmarker and Hand Landmarker are the public `.task` files, default `full`. They were trained on ordinary people. Nothing in this repo fine-tunes those weights.

Audio onsets and tempo come from aubio. Timing is a grid fitted to the player's own hits, not a click, unless they played to one. Flams inside 40 ms are merged into one onset.

Coaching is templates in `analyzer/app/coaching.py`. Same numbers always produce the same sentences. It does not judge posture, elbow angle as a grade, flam quality, or stick height. "Wrist travel" is image Y, so a side camera shows stroke height and a front camera mostly does not. Version 3 of coaching (hide weak video verdicts) is on a branch, not on the process that is serving.

`analyzer/tuning.temp.json` is a threshold file, not weights. It was fit on 13 Creative Commons BY clips in `D:\Stickitout-dataset\reference-videos`. Overrides: `hand_source=strike_first`, `strike_min_prominence=0.012`. Composite score on that set went from 17.35 to 35.49. Median video-to-hit match stayed about 29%. Sticking was only a few points above shuffled hands. The server loads it only when `SIO_TEMP_TRAINING=1`. The 60-take pass used `SIO_TEMP_TRAINING=0` on purpose. No new fit has been run on the 60. Delete the file and restart to restore shipped thresholds.

## How a take is scored

1. aubio finds onsets. Notes closer than `min_ioi_ms` (40) become one onset, so a flam is one sound.
2. MediaPipe writes pose and hand points per frame. `build_tracks` keeps frames where both wrists are visible enough.
3. `detect_strikes` turns wrist motion into a list of `{t, hand}`.
4. `match_strikes` pairs onsets and strikes one-to-one, closest first, inside the verify window.
5. Hand for a stroke is the wrist with the faster downward velocity near the onset, unless `hand_source` is `strike_first`, which copies the matched strike's hand.
6. `app/coaching.py` writes the sentences from those counts.

Reports live beside each clip as `analysis.json`. Landmark caches are `cache/landmarks.json.gz`, which is how the 60 were remeasured without running MediaPipe again.

## Ship

All three commands run from the Stickitout repo root. Marketing is its own upload. Member and admin are one Cloudflare Worker, so one deploy publishes both hosts.

### Marketing

https://stickitoutdrums.com/

Needs `.env` with `SFTP_HOST`, `SFTP_USER`, and `SFTP_PASSWORD`. Copy `.env.example` if `.env` is missing.

```bash
npm run shipit
```

That runs three steps:

1. `npm run build` writes the Astro site to `dist/`.
2. `node scripts/ship-check.mjs` stops the ship if a secret-like string is in `dist/`, or if `dist/api/capture.php` is missing.
3. `node shipit.js` SFTPs `dist/` to the IONOS web root. Before the upload it writes `capture-config.php` into `dist/` from `.env`. Paths under `data/leads` are not uploaded, so the server's lead backup stays.

`npm run shipit:only` skips the build and the secret scan and uploads the `dist/` already on disk.

When it finishes, the script prints https://stickitoutdrums.com/ and https://stickitoutdrums.com/api/capture.php. Confirm the ship there.

### Member and admin

https://member.stickitoutdrums.com/
https://admin.stickitoutdrums.com/

Both hosts are routes on the Worker `stickitout-portals` (`workers/app`). One deploy updates both. It does not touch the marketing site.

If a new SQL file in `workers/app` must exist before the new code runs, apply it first:

```bash
npx wrangler d1 migrations apply stickitout --remote --config workers/app/wrangler.jsonc
```

Then:

```bash
npm run portal:deploy
```

That is `wrangler deploy --config workers/app/wrangler.jsonc`. Confirm the member host and the admin host after it finishes. The same deploy also updates `https://stickitout-portals.zayyo.workers.dev/`.

Secrets (`RESEND_API_KEY`, `ANALYZER_ORIGIN`, `ANALYZER_TOKEN`, `LEAD_INGEST_SECRET`) are already on the Worker. A normal deploy does not replace them. Change one only with `npx wrangler secret put <NAME> --config workers/app/wrangler.jsonc`.

None of these commands restart the analyzer on the studio PC.
